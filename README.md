# OpenGames

Платформа интерактивных сценариев с AI-сценаристом. Каталог из 42 игровых пакетов, ход за ходом разыгрываемых по состоянию партии и истории игрока, авторизация, профили AI-провайдеров и локальный соавторский режим.

## Требования

- Node.js 22 или новее — сервер запускается через `--experimental-strip-types`
- свободный порт `3000` (меняется переменной `PORT`)

## Запуск

```bash
npm install
npm run dev
```

Каталог сценариев: <http://localhost:3000/#/games>

Проверка состояния:

```bash
curl http://localhost:3000/api/health
```

Подробная инструкция по первому запуску — в [runbook.md](runbook.md).

## Переменные окружения

Режим LLM включается переменными из [.env.example](.env.example). Файл `.env` не публикуется и не должен попадать в Git.

```bash
cp .env.example .env
```

Обязателен `OPENGAME_SECRET` — случайная строка длиной не менее 32 символов, из неё выводится ключ шифрования пользовательских API-ключей. Сервер отказывается стартовать с заглушкой. Остальные переменные необязательны: без них доступен локальный сценарий и режим соавторов.

## Проверка

```bash
npm run typecheck
```

Сервер валидирует каждый пакет сценария при старте, поэтому несовместимый пакет приводит к отказу запуска, а не к ошибке в игре.

## Процесс изменений

Каждое изменение проходит три обязательных шага.

**1. Фиксация в репозитории.** Изменение оформляется коммитом и попадает в публичный репозиторий GitHub. В репозиторий не публикуются `.env`, каталог `data/`, резервные архивы, учётные данные и токены.

**2. Локальная проверка.** До публикации выполняется `npm run typecheck`, затем сервер запускается в чистом каталоге с экспортированного дерева и проверяются доступность `/api/health`, число игр, прохождение реального хода и отдача статики. Непроверенное изменение не публикуется; при неуспешной проверке исправляется причина, а не ослабляется проверка.

**3. Публикация.** Изменение выкладывается на production строго по последовательности:

```
резервная копия текущего релиза (с учётными данными)
  → выкладка
  → перезапуск и проверка
  → скачивание копии на локальную машину
  → удаление копии с production
```

Копия создаётся до выкладки, хранится локально и удаляется с production сразу после успешной проверки. Между выкладками резервная копия на сервере не остаётся; каждая следующая выкладка начинается с новой копии. При неуспешной проверке предыдущий релиз восстанавливается из локального архива, неудачная копия удаляется с production.

## Как устроен ход

Игровые пакеты не содержат заранее написанных ответвлений и готовых ответов на системные действия. Арка сюжета хранится в `world.constants.storyArc` как ориентир: этапы, улики двух поворотов и три направления развития с ценой выбора. Конкретное продолжение и следующие действия формирует AI по текущему состоянию и истории. Если сценарист недоступен или не ответил вовремя, runtime собирает короткий локальный ответ по выбранному действию и предлагает три новых свободных действия.
