# OpenGames

Платформа интерактивных сценариев с AI-сценаристом. Каталог из 42 игровых пакетов, ход за ходом разыгрываемых по состоянию партии и истории игрока, авторизация, профили AI-провайдеров и локальный соавторский режим.

## Требования

- Node.js 22 или новее — сервер запускается через `--experimental-strip-types`
- свободный порт `3000` (меняется переменной `PORT`)

## Запуск

```bash
npm install
npm run dev
```

Каталог сценариев: <http://localhost:3000/#/games>

Проверка состояния:

```bash
curl http://localhost:3000/api/health
```

Подробная инструкция по первому запуску — в [runbook.md](runbook.md).

## Переменные окружения

Режим LLM включается переменными из [.env.example](.env.example). Файл `.env` не публикуется и не должен попадать в Git.

```bash
cp .env.example .env
```

Обязателен `OPENGAME_SECRET` — случайная строка длиной не менее 32 символов, из неё выводится ключ шифрования пользовательских API-ключей. Сервер отказывается стартовать с заглушкой. Остальные переменные необязательны: без них доступен локальный сценарий и режим соавторов.

## Проверка

```bash
npm run typecheck
```

Сервер валидирует каждый пакет сценария при старте, поэтому несовместимый пакет приводит к отказу запуска, а не к ошибке в игре.

## Процесс изменений

Каждое изменение проходит три обязательных шага.

**1. Фиксация в репозитории.** Изменение оформляется коммитом и попадает в публичный репозиторий GitHub. В репозиторий не публикуются `.env`, каталог `data/`, резервные архивы, учётные данные и токены.

**2. Локальная проверка.** До публикации выполняется `npm run typecheck`, затем сервер запускается в чистом каталоге с экспортированного дерева и проверяются доступность `/api/health`, число игр, прохождение реального хода и отдача статики. Непроверенное изменение не публикуется; при неуспешной проверке исправляется причина, а не ослабляется проверка.

**3. Публикация.** Изменение выкладывается на production строго по последовательности:

```
резервная копия текущего релиза (с учётными данными)
  → выкладка
  → перезапуск и проверка
  → скачивание копии на локальную машину
  → удаление копии с production
```

Копия создаётся до выкладки, хранится локально и удаляется с production сразу после успешной проверки. Между выкладками резервная копия на сервере не остаётся; каждая следующая выкладка начинается с новой копии. При неуспешной проверке предыдущий релиз восстанавливается из локального архива, неудачная копия удаляется с production.

## Страницы и индексация

Индексируется только публичная часть: главная, каталог сценариев и страница сценария. Всё остальное закрыто от поисковых систем. Правило обязательно для любой новой страницы и проверяется перед публикацией.

| Страница | Адрес | Индексация |
| --- | --- | --- |
| Главная, каталог, сценарий | `/`, `/#/games`, `/#/play/...` | разрешена |
| Публичная оферта | `/legal/terms` | запрещена |
| Политика конфиденциальности | `/legal/privacy` | запрещена |
| Админка | `/admin` | запрещена, доступ только администратору |
| API | `/api/...` | запрещена |

Страница закрывается от поиска тремя способами сразу, они применяются вместе:

1. `<meta name="robots" content="noindex, nofollow, noarchive, nosnippet">` в `<head>` страницы;
2. заголовок `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet` в ответе сервера — работает даже если разметка будет удалена;
3. строка `Disallow:` в [`web/robots.txt`](web/robots.txt) для этого префикса.

Порядок регистрации маршрута в [`src/server.ts`](src/server.ts): отдавать страницу из `legalPages` с заголовками `noIndexHeaders` либо отдельным маршрутом с ними же, после чего внести префикс в `robots.txt`. Название файла и адрес должны совпадать по регистру.

Проверка перед публикацией:

```bash
curl -sI http://localhost:3000/legal/terms | grep -iE 'HTTP/|x-robots-tag|content-type'
curl -s http://localhost:3000/legal/terms | grep -c 'name="robots" content="noindex'
curl -s http://localhost:3000/robots.txt
```

Ожидается: `200`, заголовок `X-Robots-Tag` с `noindex`, одна строка `name="robots"` со значением `noindex`, и `Disallow: /legal/` в `robots.txt`. Если в `robots.txt` закрыт префикс, `meta robots` всё равно обязателен: закрытый от обхода адрес не отдаст поисковику указание убрать страницу из выдачи, если она была проиндексирована ранее.

Реквизиты исполнителя не хранятся в файлах: они заполняются администратором во вкладке «Правовые документы» и лежат в `data/legal.json` (каталог `data/` не публикуется).

Реквизиты исполнителя — **одна сущность для обоих документов**. В админке три блока: общие реквизиты исполнителя и отдельно поля оферты и поля политики. Форма организации, ФИО или наименование, ИНН, КПП, ОГРН, адрес, телефон, почта и ответственный за персональные данные заполняются один раз и подставляются в оба шаблона — разойтись они не могут. Публикация каждого документа зависит и от общих реквизитов, и от его собственных полей: не заполнены общие — не опубликован ни один; не заполнены поля политики — оферта видна, политика отдаёт `503`.

Пока обязательные поля пусты, документ посетителю не отдаётся: сервер отвечает `503` страницей «документ не опубликован», текст документа при этом не раскрывается. Администратор видит черновик со всеми полями, а черновой блок из опубликованного текста вырезается.

Форма организации — ИП, ООО или самозанятый — определяет состав обязательных полей: КПП требуется только у ООО, ОГРН и адрес не запрашиваются у самозанятого, а налоговый режим и способ выдачи чеков для самозанятого подставляются автоматически («НПД» и «в приложении „Мой налог“»). Поля, неприменимые к выбранной форме, выводятся в документе как «не применяется» и публикацию не блокируют.

Добавление нового поля: запись в `EXECUTOR_FIELDS`, `TERMS_FIELDS` или `PRIVACY_FIELDS` в [`src/core/legal.ts`](src/core/legal.ts) с указанием применимых форм, плюс элемент `<span class="todo" data-legal="ключ.поля">{{ключ.поля}}</span>` в шаблон. **Значение в `data-legal` и в `{{}}` должно совпадать**: подстановка заменяет элемент целиком, при расхождении останется незаполненная обёртка. Общие поля используют префикс `executor.`, поля документов — `terms.` и `privacy.`. Ключи из прежней модели, где реквизиты дублировались по документам, переносятся автоматически при первом чтении файла.

Проверка публикационного gate:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/legal/terms   # 503, пока не заполнено
```

Значения вносятся только с указанием причины, которая попадает в журнал действий администратора. Перед первым платежом документы должны быть проверены юристом: проверка приёма платежей у агрегатора включает их просмотр.

## Как устроен ход

Игровые пакеты не содержат заранее написанных ответвлений и готовых ответов на системные действия. Арка сюжета хранится в `world.constants.storyArc` как ориентир: этапы, улики двух поворотов и три направления развития с ценой выбора. Конкретное продолжение и следующие действия формирует AI по текущему состоянию и истории. Если сценарист недоступен или не ответил вовремя, runtime собирает короткий локальный ответ по выбранному действию и предлагает три новых свободных действия.
